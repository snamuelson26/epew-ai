2. app/api/entrepreneurs/reminder-contact/route.ts
- Same-origin writes, verified server-side user, matching email, actor-scoped application/current preference record.
- Ignores legacy weekly_information_consent as an SMS grant.
- Independent email_information_consent and sms_consent. Compatibility weekly_information_consent reflects email only, never SMS.
- Normalized phone, server timestamp/source/language/version/full disclosure saved independently. Current version required to grant SMS. No client-forged timestamp/source trusted.
- Schema/storage failures do not report successful capture.
- Updating current actor record also invalidates the old phone's consent when a phone is changed. Saving does not clear STOP suppression.

3. supabase/migrations/20261025224814_separate_epew_sms_consent.sql
- Defaults every old record's new SMS grant to FALSE. No conversion/backfill of general consent.
- Separate evidence columns and append-only event table, service-only access, RLS enabled, trigger records each submitted preference version.
- Service-only epew_can_send_application_sms(phone) checks explicit current application-update evidence and persistent STOP suppression. The latest actor preference wins even if concurrent duplicate records exist.
- Appointment recipient view now requires explicit SMS eligibility; WhatsApp remains a separate channel.
- Migration has NOT been applied to any external database.

4. lib/appointments/processMessageReminders.ts
- Rechecks SMS consent immediately before provider submission, including already queued messages; fails closed on database errors.

5. lib/communications/processSupporterOutreach.ts
- Removes automatic SMS fallback for supporter outreach. This form's application consent does not authorize supporter marketing/donation requests. Email/WhatsApp behavior otherwise unchanged.

6. app/api/twilio/sms/route.ts
- Validates provider signature, persists STOP suppression before confirming, supports HELP with support details.
- Avoids duplicate replies when provider Advanced Opt-Out already handled the keyword.
- START does not create consent or erase suppression.
- Local behavior tested only. This is a Twilio webhook, NOT a Sent webhook. Sent STOP/HELP configuration and delivery to application suppression must be inspected/verified before claiming Sent integration complete. Do not point a Sent webhook to this signature-specific endpoint.
